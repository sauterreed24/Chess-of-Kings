# Audit 2026-04

## Executive Summary

The most damaging LinkedIn-facing issue is not a chess bug. It is legitimacy drift: the public README says the app is a polished, installable, accessibility-first PWA with about 6,000 TypeScript LOC, but verification found 9,326 production TS LOC, no service worker, broken root-relative public links on GitHub Pages, no Open Graph/Twitter image metadata, a stale latest GitHub Release, and `npm test` exiting non-zero despite 214 passing tests. A recruiter or AI screener will trust the repo less when the first measurable claims do not line up.

The fastest high-leverage fix is a repo-polish PR: fix GitHub Pages asset/link paths, add OG/social metadata and a 1200x630 image, add `SECURITY.md` and templates, tag a current release, and make `npm test` exit cleanly. That is more valuable for first-90-second review than another UI flourish.

## Disagreements With Claude's Choices

1. Claude optimized visible feature breadth while leaving the test gate non-green. A repository aimed at recruiters cannot have `214 passed` followed by exit code 1; the failed command matters more than another dossier embellishment because CI truth is a stronger signal than feature count.
